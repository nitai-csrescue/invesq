Build a polished mockup web app called “CS Rescue” that visualizes a company’s customer lifecycle architecture in a highly visual, lightweight, intuitive way.

The app should feel like a hybrid of:
- a modern architecture diagram
- a product operating system
- a visual systems map
- a lightweight executive command center

This is NOT a text-heavy dashboard. It should be visually led, minimal in copy, easy to understand at a glance, and feel closer to a clean Miro / Lucidchart / Figma prototype than a dense BI dashboard.

Core idea:
The app shows a high-level view of an organization’s product architecture across the full customer lifecycle, and lets users click into parts of the architecture to reveal deeper detail. It should be company-agnostic in structure, but for now use the placeholder company name “CS Rescue.”

The main use case:
A professional services / financial services software company wants to see how customer-facing lifecycle motions connect to delivery, product capabilities, systems, integrations, data sources, and downstream teams.

Important design direction:
- extremely visual
- lightweight on text
- minimal clutter
- intuitive information hierarchy
- elegant and modern
- premium enterprise SaaS feel
- dark mode by default
- animation should be subtle and smooth
- cards and nodes should feel tactile and clickable
- use whitespace generously
- use iconography, color, grouping, connection lines, and progressive disclosure instead of large blocks of text

Do NOT make this feel like a traditional analytics dashboard with too many panels and paragraphs.
Do NOT overload the screen with explanatory text.
Do NOT make it look like a generic admin panel.

--------------------------------------------------
PRODUCT CONCEPT
--------------------------------------------------

The app should center around a visual architecture map with 3 major layers:

1. Lifecycle Motions
These represent the customer lifecycle and should appear as a top row or top-level layer:
- Pre-Sales
- Contract / Signature
- Implementation / Onboarding
- CSM / Upsell
- Support

2. Delivery / Orchestration Layer
This is the middle layer and should visually connect the top lifecycle motions to the bottom platform systems:
- Forward-Deployed Delivery
- Lifecycle Playbooks
- Deployment Intelligence

3. Shared Platform / Systems Layer
This is the foundation layer and should represent reusable backend/product capabilities:
- Data Orchestration
- Decisioning Engine
- Compliance & Controls
- Partner Hub
- Analytics / BI
- CRM / Customer Data
- Case Management / Ticketing
- Document / Knowledge Layer
- API Gateway / Integration Hub

Each node should be clickable.

When clicked, a node should reveal a lightweight drill-in panel with:
- short title
- one sentence description max
- 3–5 key capabilities shown as chips or bullets
- key systems/resources connected to it
- sample KPIs or metadata
- related downstream nodes / dependencies

--------------------------------------------------
PRIMARY UX
--------------------------------------------------

Build the app with these main views:

1. Main Architecture View
This is the default landing screen.
It should show:
- company name “CS Rescue” in the header
- a large architecture map occupying most of the screen
- nodes arranged in clear grouped layers
- visible relationships / connectors between layers
- hover states and selected states
- zoom/pan feel if possible
- a right-side detail drawer or floating inspector panel on click

2. Resource / Systems Explorer
A secondary view or tab that shows all connected resources and systems.
It should allow the user to see and manage:
- Salesforce / CRM
- proprietary API endpoints
- internal data warehouse
- BI tools
- support/ticketing tools
- contract/signature tools
- document repositories
- cloud storage / object storage
- compliance systems
- identity / auth providers
- event streams / messaging
- customer data platforms
- operational databases

This view should show resource cards or a network-style relationship map.
It should feel modular and extensible.

3. Deployment Workspace
A view focused on a single customer rollout / deployment.
This should show:
- selected customer/account
- lifecycle stage progress
- linked systems/resources
- workstreams
- major blockers / risks
- implementation dependencies
- system readiness
- status indicators
Use visual status blocks and minimal text.
