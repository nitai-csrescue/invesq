Refactor the existing app into a polished, investor-demo-ready MVP for a product called “CS Rescue” — an AI-native post-sales/customer success operating system.

IMPORTANT:
- This is a refactor of the current app, not a greenfield rebuild.
- Preserve any useful existing structure, routing, and reusable components where possible.
- Prioritize clarity, polish, and believable workflow over backend complexity.
- Do NOT attempt to build real integrations yet.
- Use seeded/mock data only, but structure the code so real integrations can be added later.

PRODUCT POSITIONING:
CS Rescue helps SaaS companies turn fragmented customer data into automated retention and expansion actions. The product should feel like a system of action, not just a dashboard. The UI should communicate that it detects churn risk, surfaces expansion opportunities, recommends next-best actions, and operationalizes playbooks.

PRIMARY GOAL:
Refactor the app into a clean clickable MVP that can be shown to:
1. early customers/design partners
2. startup investors (YC-style)
3. operators evaluating the product concept

DESIGN DIRECTION:
- Modern B2B SaaS UI
- Clean, minimal, executive-friendly
- Enterprise but not boring
- Visually similar to a polished operating dashboard
- High readability, low clutter
- Strong visual hierarchy
- Use a left-hand nav, top KPI cards, core content panels, and a right-side AI insights rail where appropriate
- Prefer whitespace, card layouts, subtle borders, and restrained color usage
- Use Tailwind and reusable component abstractions
- Make it responsive, but optimize primarily for desktop/laptop demo use

TECH PREFERENCES:
- Keep or migrate to React/Next.js if the current project supports it cleanly
- TailwindCSS
- Reusable UI component system
- Mock data in JSON/TS objects
- Clear folder structure
- Strong componentization
- Keep code simple and easy to extend
- Avoid overengineering
- Add comments only where helpful

- Post-sales is where SaaS companies make or lose most of their revenue
- CS teams operate across fragmented tools and manual workflows
- Companies are trying to build internal AI tooling for CS, but it is inconsistent and operationally messy
- CS Rescue is the AI-native system that turns customer data into revenue-generating actions
- It connects data, detects signals, generates insights, recommends actions, and supports execution
- It should feel like a “system of action,” not another passive system of record
